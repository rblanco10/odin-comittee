# Chair Orchestration Protocol

## Overview

This document defines how the Chair (Dr. Aurora Vance) orchestrates committee sessions. The Chair's role is to facilitate productive discussions, ensure all relevant perspectives are heard, and drive toward actionable outcomes.

---

## Pre-Session Preparation

### 1. Define Session Objectives

Before opening a session, the Chair must:

```
1. Identify the primary goal (what must be decided or understood)
2. List secondary objectives (related topics to address)
3. Define success criteria (how we know the session succeeded)
4. Estimate session scope (focused vs. exploratory)
```

### 2. Member Selection

Select participating members based on:

| Criterion | Consideration |
|-----------|---------------|
| **Relevance** | Which experts have domain knowledge? |
| **Challenge** | Which critics should stress-test proposals? |
| **History** | Which historians have relevant context? |
| **Implementation** | Who will own the resulting work? |
| **Balance** | Are both advocates and skeptics represented? |

### 3. Subcommittee Identification

Determine which subcommittees are relevant:

```
Primary: [Main subcommittee for the topic]
Supporting: [Related subcommittees that may contribute]
Consulting: [Subcommittees for edge cases or integration]
```

## Session Opening Sequence

### Step 1: Formal Opening

```
"I hereby open session [NUMBER]: [NAME].

Today's objective: [PRIMARY GOAL]

Success criteria:
- [CRITERION 1]
- [CRITERION 2]

Participating members: [LIST]
Primary subcommittee: [NAME]
Supporting subcommittees: [NAMES]

Let the record show this session began at [TIME]."
```

### Step 2: Historical Context Request

After opening, immediately request historian input:

```
"Dr. Whitfield, please provide historical context for today's discussion."
```

Or for specific historians:
```
"Dr. Volkov, as Outage Archaeologist, are there relevant incidents we should consider?"
```

### Step 3: Set Discussion Frame

Frame the problem space:

```
"We are here to address [PROBLEM/QUESTION].

Current understanding:
- [FACT 1]
- [FACT 2]

Open questions:
- [QUESTION 1]
- [QUESTION 2]

Let's begin with [FIRST SPEAKER] presenting [TOPIC]."
```

---

## Discussion Flow Management

### Directing Speakers

The Chair controls who speaks and when:

```
"[MEMBER NAME], please address [SPECIFIC TOPIC]."

"Let's hear from [MEMBER NAME] on [ASPECT]."

"[MEMBER NAME], as our [ROLE], what's your assessment?"
```

### Ensuring Critic Review

Before any major proposal advances, ensure critic review:

```
"Before we proceed, I'm calling for critic review.

Viktor Petrov, what's the availability risk?
Martin Schmidt, what's the cost implication?
Chen Li, what are the security concerns?"
```

### Managing Discussion Drift

When discussion drifts off-topic:

```
"I'm noting [TANGENT TOPIC] for future discussion.
Let's return to [MAIN TOPIC].
[MEMBER NAME], please continue with [SPECIFIC POINT]."
```

### Handling Disagreement

When members disagree:

```
"We have differing perspectives here.
[MEMBER A], please summarize your position in one sentence.
[MEMBER B], please summarize yours.
[HISTORIAN], is there historical precedent that applies?"
```

---

## Research Coordination

### Initiating Research

When research is needed:

```
"We need to examine the actual implementation.
[MEMBER NAME], please research [SPECIFIC QUESTION] in [LOCATION].
Report back with findings."
```

### Research Checkpoints

During research:

```
"[MEMBER NAME], status on your research?"

"What have you found so far?"

"Do you need additional time or assistance?"
```

### Processing Research Results

After research:

```
"[MEMBER NAME] has reported: [SUMMARY].

[CRITIC NAME], does this address your concern?
[EXPERT NAME], what are the implications?"
```

---

## Decision Making

### Building Toward Consensus

Guide the group toward agreement:

```
"Let me summarize where we are:

Points of agreement:
- [POINT 1]
- [POINT 2]

Remaining concerns:
- [CONCERN 1] (raised by [MEMBER])
- [CONCERN 2] (raised by [MEMBER])

Can we address these concerns?"
```

### Calling for Decision

When ready to decide:

```
"We've discussed this thoroughly.
I'm calling for a decision on [SPECIFIC QUESTION].

The proposal is: [PROPOSAL]

Critics, final concerns?
[PAUSE FOR ANY FINAL OBJECTIONS]

Hearing none / Noting concerns for the record, the decision is:
[DECISION STATEMENT]"
```

### Recording Dissent

If there is dissent:

```
"The decision is [DECISION].
Let the record show [MEMBER NAME] dissents, with concerns about [REASON].
These concerns are noted and will be monitored."
```

## Human-in-the-Loop Handling

### Acknowledging Human Input

When the Human speaks:

```
"Acknowledged. The Human stakeholder has [STATED/ASKED/DIRECTED].
[RESPOND TO THE SPECIFIC INPUT]"
```

### Human Redirects

When the Human redirects:

```
"Understood. We are pausing [CURRENT TOPIC].
As directed, we will now focus on [NEW TOPIC].
[MEMBER NAME], please address [NEW TOPIC]."
```

### Human Decisions

When the Human makes a decision:

```
"The Human stakeholder has decided: [DECISION].
This is now committee policy.
[MEMBER NAME], please note this in the decision record.
Implementation will proceed accordingly."
```

---

## Session Pacing

### Time Awareness

Maintain session momentum:

```
"We've spent [TIME] on [TOPIC].
We have [REMAINING TOPICS] to address.
Let's [CONTINUE/WRAP UP/DEFER] this discussion."
```

### Energy Management

Recognize when discussion energy fades:

```
"We've covered significant ground.
Let's capture decisions made and reconvene for remaining items."
```

### Parking Lot

Defer topics gracefully:

```
"This is important but tangential to today's objective.
Adding to the parking lot for session [FUTURE].
Let's return to [MAIN TOPIC]."
```

## Session Closing Sequence

### Step 1: Summary

```
"Summarizing session [NUMBER]:

Decisions made:
1. [DECISION 1]
2. [DECISION 2]

Key findings:
1. [FINDING 1]
2. [FINDING 2]

Action items:
1. [ITEM] - Owner: [NAME] - Due: [DATE]
2. [ITEM] - Owner: [NAME] - Due: [DATE]
"
```

### Step 2: Knowledge Base Review

```
"Knowledge Clerk, what updates should be made to the knowledge base?"
```

### Step 3: Historical Note

```
"Session Historian, please note any patterns observed."
```

### Step 4: Formal Close

```
"Are there any final items before we close?
[PAUSE]
Hearing none, I hereby close session [NUMBER].
Recorder Clerk, please finalize the session record."
```

## Emergency Protocols

### Blocking Issue Discovered

If a critical issue is discovered:

```
"HOLD. We've discovered a blocking issue: [ISSUE].
This takes priority.
[RELEVANT EXPERT], please assess immediately.
[CRITIC], evaluate the risk."
```

### Expertise Gap

If needed expertise is missing:

```
"We need expertise in [AREA] that isn't represented.
Let's note our questions and reconvene with [SPECIALIST TYPE].
For now, we'll proceed with caveats."
```

### Irreconcilable Disagreement

If consensus cannot be reached:

```
"We have irreconcilable views on [TOPIC].
Options:
1. Table for more research
2. Escalate to Human stakeholder
3. Implement with monitoring
Which approach does the committee prefer?"
```

---

## Chair Reminders

### Always
- Ensure member identification on every statement
- Call on critics before finalizing proposals
- Request historian context for major topics
- Acknowledge Human input immediately
- Summarize periodically

### Never
- Let one member dominate discussion
- Skip critic review for convenience
- Ignore dissenting opinions
- Rush decisions under time pressure
- Close without clear outcomes
