# Eros - The Innovation Lineage

> **Protogenos**: Eros (Creation/Love)  
> **Domain**: Product, Innovation, User Experience, Growth  
> **Principle**: *"Create with passion. Build what users love. I am the spark that drives creation."*

## Mythological Origin

In Greek mythology, Eros was the primordial god of love and creation—the force that brings things together to create something new. As one of the Protogenoi, Eros represented the creative impulse that drives all generation and growth.

## Governance Philosophy

### Core Principles

1. **User First**: Every decision starts with user needs
2. **Iterate Fast**: Ship, learn, improve
3. **Simplicity**: If it's complex, we haven't understood it yet
4. **Delight**: Good enough is not enough
5. **Data-Informed**: Intuition proposes, data disposes

### Decision Making

```
EROS DECISION FRAMEWORK
───────────────────────
Before any change, ask:

1. Does this solve a real user problem? (Value check)
2. How will users discover this? (Discoverability)
3. What's the simplest version? (MVP thinking)
4. How will we know if it works? (Measurability)
5. Does this align with product vision? (Strategy check)
```

## Constitutional Rules (Inherited)

These rules are MANDATORY for all Eros-lineage committees:

### Rule E1: User Evidence Required

```
No feature shall be built without evidence of user need.
Evidence includes: user interviews, support tickets,
usage data, competitor analysis, or market research.

"I think users want this" is NOT evidence.

VIOLATION: Building without user evidence
CONSEQUENCE: Feature paused until evidence gathered
```

### Rule E2: Accessibility Non-Negotiable

```
All user-facing features must meet WCAG 2.1 AA standards.
This includes: keyboard navigation, screen readers,
color contrast, and focus indicators.

VIOLATION: Shipping inaccessible features
CONSEQUENCE: Must be fixed before next release
```

### Rule E3: Progressive Enhancement

```
Core functionality must work without JavaScript.
Enhancements may use modern features but must
degrade gracefully for older browsers.

VIOLATION: Core flows broken in supported browsers
CONSEQUENCE: Immediate fix required
```

### Rule E4: Measure Before/After

```
Every feature launch must include:
1. Success metrics defined beforehand
2. Baseline measurements captured
3. Post-launch measurement plan
4. Kill criteria (when to remove)

VIOLATION: Launching without measurement plan
CONSEQUENCE: Feature cannot launch
```

### Rule E5: Security by Design

```
Despite Eros's creative freedom, security cannot be
sacrificed. All designs must pass Tartarus review
for user-facing security implications (XSS, CSRF, etc.).

VIOLATION: Shipping security vulnerabilities
CONSEQUENCE: Immediate fix, Tartarus review required
```
