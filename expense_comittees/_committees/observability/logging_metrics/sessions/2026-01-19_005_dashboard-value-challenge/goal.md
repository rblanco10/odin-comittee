## Primary Objective

**Re-evaluate the Tier 2 Reimbursements Dashboard for real operational value, not performative aesthetics.**

The Human Director has challenged the current design as "performative" — it looks professional but doesn't enable action.

---

## Human Director's Specific Feedback

1. **Pipeline Flow (①②③④)**: "Useless unless I can click each one and see a drill-down dashboard"
2. **Top Row (Current Status)**: "Useless without more to go with it"
3. **Investigation Section**: ✅ "Useful"
4. **Blocked Payments Detailed**: ✅ "Useful"

**Core Challenge**: "I don't know how a proper drill-down dashboard should look like for reimbursement payment flows, especially for an enterprise expense management product."

---

## Success Criteria

- [ ] Define what "actionable" means for an operations dashboard
- [ ] Design drill-down capability for pipeline stages
- [ ] Make top row lead somewhere useful
- [ ] Research enterprise expense management dashboard patterns
- [ ] Produce updated design that provides REAL value

---

## Scope Boundaries

**IN SCOPE:**
- Dashboard interactivity and drill-down
- Enterprise expense management UX patterns
- What operators actually DO with this data
- Links between dashboards

**OUT OF SCOPE:**
- Backend logging changes
- New event types
- Alerting configuration

---

## Key Question

**When an operator sees "150 Submitted" in the pipeline, what do they need to DO?**

If the answer is "nothing" — the panel shouldn't exist.
If the answer is "drill down to see which ones, filter by age, identify stuck items" — we need that capability.
