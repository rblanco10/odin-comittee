## Executive Summary

Committee investigated why reimbursement pushes to NetSuite were failing with "skipped query run due to filter being false" after clicking "Sync to ERP". Cross-branch analysis revealed that similar issues in the card transaction flow had been fixed in `erp-sync/jan-2-2026`.

**Key Finding:** The `AshOban.Changes.BuiltinChanges.run_oban_trigger/1` may not properly pass tenant context for multi-tenant resources. The card transaction flow uses a manual trigger pattern that explicitly passes the tenant.

**Decision:** Apply the same patterns from the card transaction fixes to the reimbursement flow.

---

## Investigation Process

### 1. Symptom Analysis (Observability Analyst)

Identified the key error pattern:
```
[debug] FlameTeampayPayables.EmberErp.Resources.PushRequest.pending_push_requests: 
        skipped query run due to filter being false
```

This indicates Ash is short-circuiting the query because a required filter condition cannot be satisfied.

### 2. Cross-Branch Analysis (Code Archaeologist)

Examined commit `4dfa82956` in `erp-sync/jan-2-2026`:
- **SC-2026-01-02-006**: Added idempotency check before creating PushRequest
- **SC-2026-01-02-007**: Manual `AshOban.run_trigger` with explicit tenant
- **SC-2026-01-02-008**: Bypass policy for worker read action
- **SC-2026-01-02-009**: `authorize?: false` in reactor queries

### 3. Pattern Comparison (Sync Architect)

| Component | Card Transaction (Working) | Reimbursement (Failing) |
|-----------|---------------------------|------------------------|
| Oban Trigger | Manual `run_trigger(result, trigger, tenant: ...)` | `BuiltinChanges.run_oban_trigger/1` |
| Idempotency | `find_existing_push_request` check | None |
| Reactor Auth | `authorize?: false` | `authorize?: false` ✅ |
| Worker Read | `multitenancy :allow_global` | `multitenancy :allow_global` ✅ |

### 4. Root Cause Determination (AshOban Expert)

The `BuiltinChanges.run_oban_trigger/1` internally calls `AshOban.run_trigger/2` which may default the tenant context differently than the explicit call with `tenant: result.workspace_id`.

---

## Fixes Approved

### Fix 1: Manual AshOban Trigger (Critical)

Replace the built-in change with explicit tenant passing:

```elixir
change fn changeset, _context ->
  Ash.Changeset.after_action(changeset, fn _changeset, result ->
    if result.status == :pending do
      trigger = AshOban.Info.oban_trigger(result.__struct__, :process_push)
      if trigger do
        Logger.info("PushRequest: Triggering immediate processing for #{result.id}")
        AshOban.run_trigger(result, trigger, tenant: result.workspace_id)
      end
    end
    {:ok, result}
  end)
end
```

### Fix 2: Idempotency Check (Defensive)

Add `find_existing_reimbursement_push_request/3` before creating new push requests.

### Fix 3: Payment Idempotency (Consistency)

Add `find_existing_payment_push_request/3` for payment sync.
