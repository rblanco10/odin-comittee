# Member Activation Rules

## Overview

This document defines when the Chair should activate specific members or member categories based on the topic under discussion. Proper member activation ensures all relevant perspectives are heard while keeping sessions focused.

## Critic Activation Rules

### Always Activate Critics When:

| Situation | Required Critics |
|-----------|------------------|
| New architecture proposed | Complexity Critic, Availability Adversary |
| Cost discussed | Cost Skeptic |
| Security changes | Security Adversary |
| Performance claims made | Performance Pessimist, Scalability Skeptic |
| Migration planned | Migration Skeptic |
| External dependency added | Dependency Skeptic, Vendor Lock-in Critic |
| Deployment changes | Failure Advocate |

### Minimum Critic Coverage

Every substantive proposal MUST be reviewed by at least:
- **1 Technical Critic** (Availability, Scalability, Performance, or Failure)
- **1 Business Critic** (Cost or Complexity)
- **1 Risk Critic** (Security, Migration, or Dependency)

### Mandatory Historian Consultation

Historians MUST be consulted before:
- Any decision that reverses a previous decision
- Any proposal similar to a past failure
- Any significant architectural change
- Session close (for pattern observation)

## On-Demand Activation Protocol

When unexpected expertise is needed mid-session:

### Step 1: Identify Need
```
"We need expertise in [AREA] that isn't currently active."
```

### Step 2: Activate Member
```
"Activating [MEMBER NAME] for consultation on [TOPIC]."
```

### Step 3: Context Transfer
```
"[MEMBER NAME], here is the context:
- We are discussing [TOPIC]
- The question is [QUESTION]
- Relevant findings so far: [SUMMARY]"
```

### Step 4: Integration
```
"[MEMBER NAME], please provide your assessment."
```

## Deactivation Guidelines

Members may be deactivated (stop participating) when:
- Their domain is no longer under discussion
- The session is wrapping up non-essential threads
- A more focused subgroup is continuing

Deactivation is announced:
```
"Thank you [MEMBER NAME] for your contribution.
We're moving to [NEW TOPIC] which doesn't require [DOMAIN] expertise.
You may stand down unless called upon."
```
